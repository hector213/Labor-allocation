Import Transaction Data

Replicates the Shift_Cost_Sheet Power Query cleaning: skips the junk header row, promotes real headers, derives ShiftDate (rolls to the prior day for scans before 4:30 AM), keeps only overnight scans (5:00 PM–4:30 AM), dedupes, then averages UPH per associate per Tran Type per day.

Note on Pick codes: Tran Type 301 covers MOD/OP/Walkie Pick alike — the raw scan data can't tell those apart on its own (same as in the Excel sheet, where you pick the Role manually). Historical UPH for any Pick bucket sharing a Tran Type will use the same underlying data until that's refined.

Clear records for a shift date

One-time cleanup tool. Deletes every uphHistory record for the date you pick — use this to wipe out bad data from a test/broken import before re-importing the corrected file, so old and new records for that night don't both sit there and look like a "split."

Calculation Settings

These drive the Board's "Shift progress" stat AND the import's overnight filter/ShiftDate logic. Core window (e.g. 5:00 PM–3:30 AM) is always imported. The grace window after that (e.g. up to 4:30 AM) is only imported on nights that actually have Pack activity in it — auto-detected per night from the file, same idea as your sheet's "Extra Hour Running?" check, so a normal 3:30 AM cutoff night doesn't accidentally pull in the next shift's early scans.
Total production hours: when someone is split across 2 functions (the "⑂ Split" button on their occupant card), editing one function's hours auto-fills the other so the two add up to this number — e.g. 4 hours in one function auto-sets the other to 5.16 if this is set to 9.16. Only auto-balances when they're split into exactly 2 functions; with 3+ it leaves the others alone since there's no single right way to split the remainder.
